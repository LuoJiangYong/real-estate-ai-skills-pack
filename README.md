# Real Estate AI Skills Pack

中国房地产市场 AI 技能工具包。

本项目面向中国房地产行业的真实工作场景，持续沉淀可复用的 AI Skill，覆盖客研、产策、品牌故事线、营销策略、社群运营顶层设计、会员与私域运营等方向。项目由作者基于多年地产 500 强企业品牌、营销、商业、社群、会员复合经验持续开发，目标是打造最全面、最实战、最适合中国房地产市场语境的 AI 工具包。

## 项目定位

房地产行业的 AI 应用不应只停留在通用写作、资料总结或简单问答。本项目希望把一线工作中的方法论、判断框架、案例经验和交付格式，沉淀为可被 AI 稳定调用的专业 Skill。

它适合用于：

- 房地产项目客研、定位、产策、投前研判
- 房地产项目品牌故事线、营销推广、媒体选题、视频脚本
- 地产品牌社群、业主运营、全民推荐、会员体系顶层设计
- 房企内部策划、营销、品牌、客关、商业、社群团队的 AI 工作流搭建
- 咨询顾问、地产操盘手、内容策划、品牌营销人员的方案辅助生成

## 项目优势

### 1. 深度贴合中国房地产市场

本项目不是通用营销模板的简单改写，而是围绕中国房地产行业的典型语境构建，包括土地研判、板块价值、竞品分层、客户结构、产品定位、社群经营、老带新、品牌溢价、城市叙事等实际问题。

### 2. 来自复合型实战经验

作者长期深耕品牌、营销、商业、社群、会员运营等复合领域，相关 Skill 更重视“可落地的判断链路”，而不是只输出漂亮但空泛的文本。

### 3. Skill 化沉淀，便于长期复用

每个模块都以独立 Skill 形式组织，包含：

- `SKILL.md`：定义触发条件、角色定位、工作流程和输出标准
- `references/` 或 `knowledge_base/`：沉淀方法论、案例库、判断模型
- `scripts/`：用于报告生成、决策树或自动化辅助的脚本

这种结构便于后续单独升级某个 Skill，也便于新增新的业务模块。

### 4. 兼顾策略、内容与交付

项目不仅关注“怎么写”，也关注“为什么这样判断”和“最终交付成什么形式”。例如产策 Skill 会强调土地、市场、客户到产品方案的推导；故事线 Skill 会结合城市叙事、视觉符号、情绪结构和传播模块；社群 Skill 会覆盖顶层设计、空间规划、平台建设、运营路径和评估模型。

### 5. 可扩展为完整房企 AI 工作台

项目未来可继续扩展为覆盖房地产全链路的 AI Skill Pack，包括：

- 客户研究
- 投前研判
- 产策定位
- 产品价值体系
- 品牌故事线
- 营销推广策略
- 媒体内容策略
- 私域与会员运营
- 社群运营顶层设计
- 老带新与全民推荐机制
- 商业与社区配套运营

## 使用方式

将需要使用的 Skill 目录复制到支持 Skill 调用的 AI 工具或 Agent 工作区中，并根据具体平台的 Skill 规范加载。

也可以直接阅读每个 Skill 的 `SKILL.md`，把其中的工作流程、输入要求和输出格式作为提示词模板使用。

推荐使用方式：

1. 先选择业务场景对应的 Skill
2. 阅读该 Skill 的 `SKILL.md`
3. 根据 Skill 要求补充项目信息、企业资料或市场资料
4. 让 AI 按 Skill 工作流输出初版成果
5. 根据实际数据、内部口径、项目阶段进行二次修订

## 项目结构

当前采用轻量结构，优先保证高内聚、低耦合、可扩展、易维护。

```text
Real Estate AI Skills Pack/
  README.md
  CHANGELOG.md
  CONTRIBUTING.md
  LICENSE.md
  LICENSE-CODE
  LICENSE-CONTENT.md
  .gitignore
  docs/
    skill-template.md
    publishing-guide.md
    roadmap.md
skills/
  real-estate-strategy/
    SKILL.md
    metadata.json
    references/
    scripts/
  real-estate-storyline/
    SKILL.md
    metadata.json
    knowledge_base/
  real-estate-community-top-design/
    SKILL.md
    metadata.json
    references/
```

版本号放入 `metadata.json` 和 `CHANGELOG.md`，不写在文件夹名称中。这样后续更新时不需要反复新增 `-1.1`、`-1.2`、`-2.0` 目录，能避免知识库和引用路径碎片化。
